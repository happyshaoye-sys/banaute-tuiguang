v2.56 缓存自动失效机制与 v2.55 计划名称修复仍然有效。

v2.55 只修一件事：计划名称。 2.54 里"计划名称"仍为空，根因不在汇总层，而在取数白名单—— 「无界-商品主体」的字段白名单没有 计划名字，源文件其实带这一列，读文件时就被丢掉。 本版放行该列，并把解析层缓存（v11→v12）与日事实缓存（v3→v5）一起换代： 这两层缓存只按"版本+文件路径+大小+mtime"命中，源文件没变就一直命中旧结果，只改白名单不升版本等于没改。 首次运行会慢一次（集团店 56 天实测 批量加载 372.58 秒 / 总计 391.90 秒），之后恢复热缓存速度。 修复后：执行表 推广明细 带 计划名:…、看板「推广计划管理」79/79 行计划名称非空、导出同步有值。

二、主推线复核怎么用

位置：💰 预算决策看板 → 🔒 阈值冻结（由运营确认） → 🔍 主推线复核。

1. 什么时候点

  • 面板提示"当前冻结值已使用 N 天（超过 14 天）"时；
  • 大促前后、季节切换、明显感觉"主推款变多了/变少了"时。

2. 点了看什么

  • 引擎建议来源：本次 56 天日事实 / 轻量 GMV 缓存；以及缓存覆盖天数（不足会显示缺口）；
  • 对照表：引擎建议值、最新一周分界、当前生效值（TH_MAIN = 50% 覆盖分界，TH_MID = 80% 覆盖分界，单位元/天）；
  • 影响预演：同一批商品、只换阈值时各角色款数怎么变（例如"若采纳建议，ZT主推 X→Y 款"）。

复核只算不动登记：想采纳建议，回到上面点 🔒 冻结 / 更新 或 ✅ 采纳引擎建议并冻结。

为什么冻结后加载会变快：角色判定只需要近 7 日 + 上一 7 日（14 天），同层基准要 28 天—— 都在这 28 天里；56 天只是"现场算引擎建议"才需要。所以冻结后主流程读 28 天，引擎建议改用轻量缓存（只存每天 宝贝ID→GMV 与 6 个 KPI 数）。

三、新品变化区（新）

位置：🆕 新品视图 → 新品变化（第 4 个子页签）。先点过「加载新品历史」才有数据。

变化类型口径你该做什么
真上新本次首次进索引，且首次在线发现日晚于上次快照日安排测款/上新动作
历史补发现本次才进索引，但首现日不晚于上次快照日（换源/补文件造成）不用当新上款处理，核对货号映射即可
消失上次在线、本次明确非在线或不再出现，且连续 2 个自然日确认是否需要清退/复活（表里带款式主图，方便认款）
恢复在线以前发现过、上次不在线、本次重新在线不算全新款，按老款继续观察
观察中（离线1天）离线 1 天，未达 2 天确认默认不占正文，需要时用"变化类型"筛出来看
  • 对比基线可切换：上次运行（默认）/ 3 天前 / 7 天前（上周同期） / 14 天前。
  • 顶部 5 个卡片 + 单独「下载新品变化CSV」；快照按"年份|店铺"保留最近 30 份。
  • 判定结果（下架 / 继续观察）翻转不作为变化列——要看结果变化请回「生命周期判定」用"判定结果"筛选。

三条边界（必须知道）： ① 源文件缺失的那一天不算消失（整天源不可用时不判定、也不写快照）； ② 回填历史（分析日不晚于上次快照日）不推进快照，页面会标"历史回算"； ③ 粒度是款式键（货号优先，缺失回退宝贝ID）——多链接只要有一条在线就算在线。

四、预算决策看板（角色层 + 阈值冻结）

列含义
决策角色ZT主推 / ZT趋势预警 / TC投产 / TD梯队 / TD候选 / CS测试 / QC回收 / 清理 / 观察
角色闸门只做减法：禁止加投→本轮归零；测试封顶→最多 500 元/周；放行加投→按错配规则原样执行
决策角色依据为什么判成这个角色；被护栏放行的会带「清仓护栏放行：日销7 … ≥ TH_MID …」
未来7日建议调整金额在错配规则基础上再乘角色系数；0 常见于"付费样本不足 100 元"或"占比差在 ±5pp 内"，属正常结论
链接投产全链接 GMV ÷ 付费（含自然流量）；推广投产 为纯广告归因口径

判定基准固定为近 7 日（近7日日均GMV = 近7日窗口GMV ÷ 7），与左侧"时间周期"无关。

清理护栏（v2.54）

衰退预警 是 36 宫格位置变化产生的弱信号：若该款 近7日日均GMV ≥ TH_MID 或 GMV趋势率 ≥ 0， 就放行给正常瀑布判定（该是主推就是主推）；清退 / 清仓 / 衰退期 / 淘汰 / 观察期 等强标记照旧判清仓。

五、操作顺序

  1. 侧边栏选日期与时间周期 → 点"加载并处理数据"。
  2. 进 💰 预算决策看板：先看摘要，再看 🔒 阈值冻结（首次使用请先冻结一次）。
  3. 冻结满 14 天或结构变化明显时，点 🔍 重算引擎建议 看影响预演，再决定是否更新冻结值。
  4. 按 决策角色 + 角色闸门 + 未来7日建议调整金额 逐款执行。
  5. 进 🆕 新品视图：点"加载新品历史 / 刷新新品历史" → 看"生命周期判定"（前 14 列含 日均访客/日均GMV）→ 切"新品变化"看进出。
  6. 交付用页面下载按钮；"导出全部Sheet"包含 预算决策看板 / 排名档对齐 / 推广计划管理 三张表。

六、边界（本次没改的事）

  • 不改 MetoX 算法、36宫格商品定位/商品周期标签、动作逻辑、退款规则与外部 v9.3 策略。
  • 不改新品判定门槛（D15/D30/D45、累计访客 300、加购率基准），本次只加"变化"视图。
  • 轻量缓存（GMV / KPI）只服务阈值引擎与看板趋势，不参与任何商品判定。
  • 30 天周期下仍按该周期自身需要加载（最多 60 天），"冻结后 28 天"只在 当日/3天/7天/15天 成立。
  • 库存与盈亏平衡线只做提示，不参与角色与预算判定。

七、启动

  1. 完整解压交付 ZIP，不要直接在压缩包内运行。
  2. 双击 启动MetoX半自动推广工具.bat。
  3. 浏览器会自动打开；实际地址以启动窗口中的 METOX_URL= 为准。
  4. 使用结束后关闭启动窗口即可停止服务。
