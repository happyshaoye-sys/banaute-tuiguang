MetoX v2.71 半自动推广工具 - 离线版使用说明

外部策略算法版本：v9.3
更新日期：2026-09-23

v2.71 修复品类分析一键复制首次可用、重新加载数据后再次失效的问题。新加载的组件会替换旧按钮并重新绑定复制事件；复制内容、19列品类展示、两种 Excel 下载口径及全部业务指标均不变。

历史 v2.58 更新

v2.58 修复品类分析首次一键复制失效，并将「全部 Sheet Excel」中的「品类分析」升级为与页面相同的19列口径。两种 Excel 的品类表固定使用品类页面全量数据，不受执行表搜索、等级和动作筛选影响；执行表本身仍按当前筛选导出。

历史 v2.57 更新

v2.57 新增执行表与 Excel 导出字段「日均访客3 / 日均访客7 / 日均访客15」，位置在日销15后、花费3前，统一保留2位小数。口径固定以分析日为终点，近N个自然日的生意参谋04商品访客数累计÷N；缺失日贡献0但分母仍为N，不随主表时间周期变化。三列只做运营观察，不参与36宫格、商品周期、预算角色、新品生命周期或动作判定；原商品访客数仍是主表所选周期累计值。

历史 v2.56 更新

v2.56 只改缓存机制，运营界面与数值不变：把「取数白名单 / 列名别名 / 源分类规则」的内容指纹编进解析层缓存键与日事实缓存载荷校验，以后改白名单缓存会自动失效，不再需要人工记得升两个缓存版本号（v2.55 就是因为漏升一次出现过“改了白名单但结果没变”）。本次不会触发重建（旧缓存载荷没有指纹字段时按兼容命中），2.55 已付过的那次约 6.5 分钟重建不会再来一次。

历史 v2.55 更新

v2.55 修复「计划名称」为空：根因是无界-商品主体的取数白名单里没有「计划名字」（源文件其实带这一列），导致推广明细/推广计划管理/导出都只有计划ID；本次放行该列，并把解析层缓存版本（v11→v12）与日事实缓存版本（v3→v5）一起自增，强制重建两次缓存（首次运行会慢一次，集团店 56 天实测约 134~392 秒，之后恢复热缓存速度）。修复后执行表「推广明细」带 `计划名:`、预算决策看板「推广计划管理」与导出 Sheet 的 `计划名称` 列有值。

历史 v2.54 更新
