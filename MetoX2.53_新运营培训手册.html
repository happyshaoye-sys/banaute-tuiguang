MetoX2.53 新运营培训手册

版本：MetoX v2.53 ｜ 发布日期：2026-09-12 ｜ 外部策略：v9.3（未变更）

一、v2.53 本次变化：新品视图

1. 新增两列“日均”指标

字段算 法怎么读
日均访客 D1_D30_商品访客数 ÷ 新品年龄 从 D1 累计到分析日的总访客，摊到每天是多少。用于判断“这款一天能拿到多少流量”。
日均GMV D1_D30_GMV ÷ 新品年龄 从 D1 累计到分析日的 GMV，摊到每天是多少。用于判断“这款一天能卖多少钱”。

新品年龄 = 分析日 − 首次在线发现日 + 1。新品年龄为 0（当天刚发现）时两列留空，不按 0 计算。

留空 = “还没有一天数据”，不等于“日均 0”。看到空白不要当成卖不动，先看 首次在线发现日 是否就是分析日当天。

2. 前 14 列固定顺序

款式主图 → 图片 → 货号 → 关联宝贝ID → 淘宝类目 → ERP建档时间 → 首次在线发现日 → 新品年龄 → D1_D30_商品访客数 → D1_D30_商品加购件数 → D1_D30_GMV → D1_D30_商品加购率 → 日均访客 → 日均GMV，其余列顺延。

  • 图片 取 款式主图 同一地址，页面上以缩略图渲染，只为肉眼核对款式，不参与任何判定。
  • 页面显示格式：日均访客 2 位小数、日均GMV 2 位小数带 ¥、D1_D30_商品加购率 为百分比。
  • 看板与导出的列顺序完全一致，页面列偏好只影响页面显示，不影响导出。

二、预算决策看板（v2.50 起，v2.52 列序变更）

看板表按固定 40 列输出，其中前三段最常用：

列含义
决策角色ZT主推 / ZT趋势预警 / TC投产 / TD梯队 / TD候选 / CS测试 / QC回收 / 清理 / 观察
角色闸门放行加投 / 禁止加投 / 测试封顶——闸门只做减法：禁止加投→本轮加投归零；测试封顶→测试期加投最多 500 元/周；放行加投→按既有错配规则原样执行。回收金额不受角色层影响。
未来7日建议调整金额在既有错配规则基础上，再乘角色系数。0 往往是“付费样本不足 100 元”或“占比差在 ±5pp 内”，属正常结论，不是漏算。
链接投产口径 = 全链接 GMV ÷ 付费（含自然流量）。与纯广告归因口径的 推广投产 并列对照。

判定基准固定为近 7 日（近7日日均GMV = 近7日窗口GMV ÷ 7），与左侧“时间周期”无关：换周期只改看数口径，不改角色结论。

阈值由运营手工冻结，引擎只给建议

  • TH_MAIN = 50% GMV 覆盖分界；TH_MID = 80% GMV 覆盖分界；单位元/天，由 7 天窗口 × 8 个窗口的覆盖法取中位数得到建议值。
  • 看板内展开 🔒 阈值冻结（由运营确认）：填运营口径 → 点 🔒 冻结 / 更新；也可 ✅ 采纳引擎建议并冻结 或 ↩ 清除冻结。
  • 冻结后角色结论立即重算，无需重新加载数据；冻结值与建议值偏离超过 ±30% 时只给复核提示，不自动改。

首次使用请先冻结一次阈值，否则会一直显示“未冻结”，角色层整体按“未判定 + 放行加投”返回（不影响既有预算决策，但角色列没有指导意义）。

三、操作顺序

  1. 侧边栏选择分析日期与时间周期，点击“加载并处理数据”。
  2. 进 💰 预算决策看板：先看摘要（周期GMV/花费、待回收、建议增加、零GMV消耗）。
  3. 展开 🔒 阈值冻结，确认或冻结本期阈值。
  4. 看 🎯 决策角色分布 掌握结构，再按 决策角色 + 角色闸门 + 未来7日建议调整金额 逐款执行。
  5. 进新品视图：进 Tab 后先点“加载新品历史 / 刷新新品历史”，再按前 14 列看款式与日均表现。
  6. 交付用页面下载按钮；“导出全部Sheet”包含 预算决策看板 / 排名档对齐 / 推广计划管理 三张表。

四、边界（本次没改的事）

  • 不改 MetoX 算法、36宫格商品定位/商品周期标签、动作逻辑、退款规则与外部 v9.3 策略。
  • 不改新品判定门槛（D15/D30/D45、累计访客 300、加购率基准），本次只加展示列与列序。
  • 库存与盈亏平衡线只做提示，不参与角色与预算判定；TH_MAIN / TH_MID 是店铺级常量，页面默认隐藏，导出保留供审计。
  • 角色层关闭时角色列仍存在但取值为空，表的形状不随开关变化。

五、启动

  1. 完整解压交付 ZIP，不要直接在压缩包内运行。
  2. 双击 启动MetoX半自动推广工具.bat。
  3. 浏览器会自动打开；实际地址以启动窗口中的 METOX_URL= 为准。
  4. 使用结束后关闭启动窗口即可停止服务。
