# MetoX v2.38 半自动推广工具

应用版本：MetoX v2.38

外部策略算法版本：v9.3（独立版本，本次未变更）

## v2.38 核心变更

- “AI任务视图”新增可选的大模型复核，统一支持 OpenAI 与 DeepSeek；模型只接收当前任务的最小必要字段，不读取商品名称、密钥或操作人信息。
- 模型输出使用固定结构，预算建议限制为增加不超过 30%、削减不超过 50%；与MetoX规则冲突、原规则低可信或无计划数据时强制人工复核，且不会自动执行推广动作。
- 新增“采纳 / 修改后采纳 / 驳回 / 暂缓”一键反馈、实际预算记录和后续结果回填；历史经验只在同淘宝类目、同规则任务类型内作为下一次建议的参考。
- 反馈默认保存到当前Windows用户的本地应用数据目录，也可用 `METOX_FEEDBACK_DIR` 指定；API密钥只从 `OPENAI_API_KEY` 或 `DEEPSEEK_API_KEY` 环境变量读取，不写入反馈文件。

## 历史 v2.37 核心变更

- 新品判定的“流量验证”只根据 D1 至当前判定节点累计商品访客数判断：累计访客达到 300 显示“已验证”，未达到才显示“待流量验证”。
- 有效数据天数仍独立决定样本是否充分，不再改变“流量验证”状态；累计访客已达标但有效数据天数不足时，保持“已验证”并继续观察。
- 本次只修复新品生命周期的状态表达和判断顺序；动销保护、加购弱势判断、同层样本门槛、既有九个 Tab、Excel 旧工作表、MetoX 算法和外部 v9.3 策略不变。

## 历史 v2.36 核心变更

- 修复新品“素材表现”和素材回测的创意数字清洗：展现量或点击量包含千分位分隔符时先按完整数值解析，再按“点击量÷展现量”计算 CTR；不修改 CTR 公式或新品下架规则。
- 主流程“加载并处理数据”不再读取新品 90 天商品历史或 45 天创意历史；新品视图在 Tab 内通过“加载新品历史 / 刷新新品历史”按钮懒加载，不影响既有九个 Tab、执行表动作和导出。
- 新品生命周期仍以首次在线发现日为 D1，D15 看 D1-D15，D30 看 D1-D30 的累计事实。
- 动销保护改为 D1 至当前判定节点内任意成交即保护：支付买家数、支付件数或 GMV 任一大于 0，直接“继续观察”并标记“动销保护”。
- 累计访客数是下架判定资格门槛：D1 至当前判定节点累计商品访客数 ≥ 300 后，才进入无成交弱势判断；累计未达 300 一律继续观察并标记“流量验证不足”。
- 无成交且累计访客达标后，再用加购承接判断：当前判定窗口有效数据天数不少于 12、同层样本不少于 20 时，商品加购率低于同层基准 B 的 80% 为主判定，加购件数作为证据强度；累计加购件数为 0 是强弱势证据。
- 新品判定表取消商品名称、商品支付转化率、访客平均价值/UV价值等非当前判定字段；素材表现表继续取消商品名称，并保留主图整体点击率和创意点击率。
- “下架判定”继续与“链接/库存现状”拆开：商品状态、在线状态和库存只作为运营信息提示，不参与“下架/继续观察”的结果判定。
- 本次修改新品视图生命周期规则、判定字段、创意数字清洗和发布说明；既有九个 Tab、执行表动作、Excel 旧工作表、MetoX 算法和外部 v9.3 策略不变。

## 版本治理

- `VERSION.json` 是唯一版本源。
- `core/version.py` 从唯一版本源派生页面显示版本。
- `scripts/release_check.py` 检查业务规则变更是否升版，并校验页面、文档、分支和阈值契约。
- `scripts/release_metox.py` 先执行发布检查，再生成带版本和日期的不可覆盖目录与 ZIP。
- Git 发布标签使用 `MetoX<版本>`，例如 `MetoX2.2`。

## 核心文件

- `core/metox_algorithm.py`：MetoX 内置算法。
- `core/v93_signal.py`：v9.3 日报信号解析。
- `core/segmentation.py`：36 宫格、风险标签、动作和优先级。
- `core/analysis.py` / `core/exporter.py`：页面和 Excel 分析口径。
- `core/merge.py` / `core/periods.py`：数据合并和周期聚合。
