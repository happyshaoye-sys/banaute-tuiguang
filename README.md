# MetoX v2.13 半自动推广工具

应用版本：MetoX v2.13

外部策略算法版本：v9.3（独立版本，本次未变更）

## v2.13 核心变更

- 执行表新增`商品加购率`：商品经营投产比的商品加购件数÷商品访客数。
- 执行表新增`推广加购率`：无界商品主体中仅15天转化、商品主体行按主体ID汇总后的总购物车数÷点击量。
- 当日及3/7/15/30天周期均按累计分子÷累计分母重算，分母为0时记0；页面按百分比显示。
- 执行表Excel与全部Sheet Excel新增`品类投放占比与ROI`Sheet，与品类分析页面使用同一口径。
- 操作文档与培训手册同步更新为 MetoX2.13。

## 延续的 v2.12 核心变更

- MetoX内置算法标签`爆发`更名为`加购爆发`；触发门槛、算法分和原因说明不变。
- AI任务视图在`MetoX算法命中`右侧新增`优先级`：P0=亏损风险/削减，P1=加预算/强主推/饱和观察，P2=加购爆发/明日之星/近3日潜力，P3=保护持有/溢出。
- 同一商品命中多个标签时取最高优先级。该列只表达MetoX标签处置顺序，不替代原有`执行优先级`P1-P4，也不改变任务策略或动作。
- 操作文档与培训手册同步更新为 MetoX2.12。

## 延续的 v2.11 核心变更

- 品类分析页“品类基础分析”表格右上角新增“一键复制”工具。
- 复制内容包含表头和当前表格全部行，采用制表符分隔，可直接粘贴到 Excel。
- 只增加复制入口，不修改品类指标、排序、汇总、导出或其他业务逻辑。

## 延续的 v2.10 核心变更

- 当`付费=0`且`计划总数=0`时，AI任务视图的`计划数据完整度`显示“无计划”，不再显示100%。
- `计划覆盖率`与`计划数据完整度`在无付费、无计划场景统一表达为“无计划”；有付费却无计划仍按数据异常处理。
- 本次只修改AI任务视图展示语义，不修改MetoX、商品策略、渠道策略或商品-计划动作逻辑。
- 新增《MetoX2.10_使用说明与运营操作顺序》，随 v2.10 发布包交付。

## 延续的 v2.9 核心变更

- 修复每日合并结果进入周期累计前丢失全量商品×计划明细及计划统计元数据的问题。
- 商品-计划动作恢复按所选周期的完整商品×PlanID数据生成，Top3仍只用于展示。
- 本次只修复数据链路传递边界，不修改MetoX、商品策略、渠道策略或商品-计划动作规则。

## 延续的 v2.8 核心变更

- 计划总数为0时，计划覆盖率显示“无计划”，不再显示100%。
- 无计划商品的AI可信度仅按商品和渠道数据计算，最高89%，并明确提示计划可信度未参与计算。
- AI任务视图及其Excel Sheet彻底移除商品名称，GMV、商品访客数、链接投产和其他字段顺序保持不变。
- 本次不修改MetoX、商品策略、渠道策略、商品-计划策略或执行表逻辑。

## 延续的 v2.7 核心变更

- AI任务主表只保留一个综合「AI可信度」，子项完整度仅在后台参与计算；选中任务后可展开查看逐项依据。
- AI任务主表移除商品名称，新增并直接透传最终执行表中的GMV、商品访客数、链接投产，不重新计算。
- 主表字段按运营执行顺序重排；本次只改展示和解释，不改变MetoX、商品策略、渠道策略、商品-计划动作、Top3或统计口径。

## 延续的 v2.6 核心变更

- 商品策略、渠道动作和商品-计划动作统一使用用户选择的当日/3天/7天/15天/30天累计窗口。
- 每日保留全部商品×PlanID指标，完整周期累计花费、归因成交、加购和点击后重算ROI、CPA，最后才按周期花费展示Top3关键计划。
- AI任务新增商品-计划级动作对象、计划总数、展示数、花费覆盖率、计划数据完整度、AI可信度和三层规则数据来源说明；这些解释字段不改变任何业务策略。
- 同一共享PlanID下不同商品允许给出不同商品-计划动作；AI任务仍是只读推广决策助手，不直接修改广告平台。

## 延续的 v2.5 核心变更

- 直购数量统一读取每日《无界-商品主体》的直接购物车数，不再使用直接成交笔数。
- 直购成本统一按所选周期的付费合计 ÷ 直购数量合计重新计算，直购数量为 0 时记 0，不再累计平台成本字段。
- 解析缓存升级为 v9，防止旧字段口径缓存继续进入执行表。

## 延续的 v2.4 核心变更

- 在「数据验收」与「执行表」之间新增只读「AI任务视图」，直接读取最终执行表 `st.session_state.df`，不重新读数、不重新合并，也不重算 MetoX、商品分层或 KPI。
- 任务页按风险优先生成放量、测试、恢复测试、稳量、渠道调整、止损、优化和人工复核八类任务，并提供优先级、三渠道动作、观察周期、成功标准、停止条件和库存提醒。
- 货号、款式主图和链接数只做原字段透传；库存只生成提醒，不改变任务类型、推广策略、渠道动作或优先级。
- 已使用从 2026-05-01 开始的前窗数据，对 7/15/30 天后窗完成独立回放验证；验证产物与口径保存在项目外部分析目录，不写入运行包。

## 延续的 v2.3 页面调整

- 侧边栏默认只保留日期、时间周期和「加载并处理数据」，缩短日常操作首屏。

- 「重新应用分界点」移动到高级设置中的自定义分界点区域，加载和重算逻辑不变。
- 库存动作页的两张表及 Excel「库存动作」均按「宝贝ID、货号、商品名称」展示，库存判定规则不变。
- 数据看板新增「AI经营日报」：跟随所选时间周期，简要说明GMV/花费/ROI变化、商品等级与品类驱动、关键词/人群/全站归因成交变化和品类ROI风险。
- 日报完全使用本地确定性计算，不调用外部AI服务；三渠道明确为广告归因成交变化，不等同于全店GMV贡献。

## 新电脑直接使用

1. 完整解压正式交付 ZIP，不要在压缩包中直接运行。
2. 双击 `启动MetoX半自动推广工具.bat`。
3. 浏览器会自动打开；实际地址以启动窗口中的 `METOX_URL=` 为准。
4. 使用期间不要关闭启动窗口。

## 版本治理

- `VERSION.json` 是唯一版本源。
- `core/version.py` 从唯一版本源派生页面显示版本。
- `scripts/release_check.py` 检查业务规则变更是否升版，并校验页面、文档、分支和阈值契约。
- `scripts/release_metox.py` 先执行发布检查，再生成带版本和日期的不可覆盖目录与 ZIP。
- Git 发布标签使用 `MetoX<版本>`，例如 `MetoX2.2`。

## 核心文件

- `core/metox_algorithm.py`：MetoX 内置算法。
- `core/v93_signal.py`：v9.3 日报信号解析。
- `core/segmentation.py`：36 宫格、风险标签、动作和优先级。
- `core/analysis.py` / `core/exporter.py`：页面和 Excel 分析口径。
- `core/merge.py` / `core/periods.py`：数据合并和周期聚合。
